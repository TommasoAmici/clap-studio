## Implementation context

The `ensemble` media view uses the existing `--drums --melody` snapshot options
together, with four percussion sounds and two pitched tracks. No production UI
behaviour changes are needed. Both appearances use the existing 3200 × 2000
full-window capture.

Validation for the combined view: debug build and all 398 tests in 86 suites
passed; both new PNGs were read and show the complete piano roll and four
drum rows at 3200 × 2000. Only existing Command Line Tools linker search-path
warnings remain.

`Sources/ClapMediaSeed/MediaLayout.swift` replaces the ring arrangement with
fixed, seeded Gaussian clouds of different widths and orientations. A few
points fall between neighbouring families. These are still demonstration
coordinates, separate from production map layout. The seeder uses them in
its mock similarity vectors too, so inspector suggestions change with the
demo layout. There is no library migration or production re-embedding change.

The scattered-map slice passed the debug build and full 398-test / 86-suite
run. Both map PNGs were read; the outer points remain inside the view.

`MediaFieldSounds.swift` adds 36 synthetic ambience WAVs at twelve demonstration
places. The seeder assigns the existing Field recording category and stores
GPS only in the scratch database. These are not recordings from the named
locations, and the media guide says so. The `places` media captures use the
existing Places view and real Apple basemap; map tiles can require network.
All twelve PNGs are regenerated with the final 420-sound demo library.

Field descriptors use `FieldRecording.aggregate`, so tempo, pitch and key stay
empty, matching the production field pipeline. Each eight-second synthetic
clip has one real full-file segment, carrying only a demonstration embedding;
no neural sound labels are fabricated.

AppKit bitmap caching drops MapKit annotation layers. A DEBUG-only helper in
`Sources/ClapStudio/DebugSnapshotPlaces.swift` captures the Apple basemap and
draws the existing runtime pin counts above its native view, below the SwiftUI
summary. The native MapKit view was verified to cap the projected
width at half the world, even with an explicit 100,000 km zoom limit. Media
captures therefore join two matching Mercator halves into a world view; normal
Places snapshots use the live camera rectangle. The full world image was read
and all twelve correctly positioned pins are visible, with no seam. Production
Places camera fitting is unchanged; revisit it separately if a native global
fit is needed.

Final Places validation: debug build and all 398 tests in 86 suites passed.
All twelve regenerated PNGs are 3200 × 2000 and were inspected together;
both Places images were read at full size with all twelve pins visible.
A read-only scratch database check found 420 OK samples, 36 placed field
recordings at twelve distinct coordinates, one full-file segment each, no
musical tempo/pitch/key in field descriptors, finite map coordinates and
unit mock vectors (maximum squared-length error 2.83e-7). The nonempty-folder
refusal still leaves its marker bytes unchanged and creates no database.
