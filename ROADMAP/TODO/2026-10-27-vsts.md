# VST Plug-ins improvements

- when I press `Preview` in the effects dialog, all inputs and buttons flash because they are disabled and re-enabled very quickly. I don't think we need to disable them
- get rid of the `rendering preview` label, the user already hears the sound, no need to show them a label
- when playing sounds through the plug-ins, there is a very noticeable latency
- pressing the button to remove a plug-in from the list crashes the app
- when bouncing samples, the audio files are too long: the silence at the end should be trimmed
- when a plug-in editor is open, I should be able to play the sample so I can edit parameters in real time

On top of these small issues, I think the current dialog/modal is not the best UX for this functionality.
I thinkg the best workflow would be to have a drawer similar to the drum machine or piano roll.
In the drawer the user would configure the chain of effects from left to right like Ableton Live.
Then from the Library list or Map the user can quickly try different samples as usual and have them play through the effects chain.

## Checklist

## Implementation context

The [README](../../README.md) describes the drawer and audition workflow.
Effects use a nonmodal horizontal drawer with native controls, matching the
existing music drawers and Apple's guidance for repeated input alongside
results. Opening Effects hides the drum and melody drawers without clearing
patterns or stopping their music; closing or disabling it returns auditions to
dry playback while preserving the session's recipe. `AppModel+Effects` forwards
visibility to `EffectsWorkbench.isOpen` rather than adding feature state to the
already large model.

The former preview rendered a complete WAV before starting playback, so its
latency grew with sample length and tails. Editors used a separate processor
and blocked the workbench. Auditions now use a persistent isolated helper,
sharing the live processor with native editors. Preview does not change the
busy state or show a rendering label. Loading, chain changes and bounce still
serialize their work.

`EffectBounce.writeInProcess` trims the final processed stereo output below
-100 dB and leaves 5 ms after the last audible frame. Dry preprocessing and
copies retain their length; trimming happens after the complete chain so
intermediate silence can still trigger a later effect. All-silent output
remains a valid short WAV. `VST3RenderTests` covers the unused extra-tail
allowance; its new test failed on the old two-second padding before the fix.

The live backend uses `VST3LiveClient` for ordered file commands and a supervised
warm `ClapVSTHost`. `VST3LiveProcessor` processes at most 512 frames with VST3's
real-time process mode. `LiveHost` queues about 40 ms of audio and reads trims,
sound edits and conversion off the main actor. The helper serializes short
processor calls and editor/controller operations on its own run loop; plug-in
code never runs in the app. Its heartbeat stops when a plug-in hangs.

A borrowed `VST3EditorSession` destroys only its editor. The processor closes
borrowed editors before releasing their shared instance; replacing a helper
kills and reaps its process, so a removed slot cannot leave a processor using
freed memory. Live blocks read the controller's latest parameters, including
`performEdit` values, rather than restoring the old recipe each block. Generic
parameter and bypass changes keep the same processor and ringing state.

`VST3LiveTests` covers short-block gain changes, bypass, editor ownership,
real-time-only processing, and cancellation. Test fixture Objective-C class
names are unique per bundle because macOS does not unload registered classes
when CFBundleUnloadExecutable is called.

`EffectsView` and `EffectRow` look up slots and parameters by stable IDs.
Bindings return the last card value after removal and ignore stale writes, so
SwiftUI can finish a render without indexing a shorter array. Removal captures
its ID before mutating the chain. Chain changes request fresh live settings
before replacing the helper; bounces request them even while an editor remains
open, preserving hidden state as well as normalized parameters.

The C bridge caches modules by canonical bundle path with a reference count.
Duplicate slots must share the factory's host context until every instance has
terminated. The duplicate-bundle test reproduced a crash without that shared
ownership and now verifies independent settings, editor closure and reopening.
Snapshot RPC replies have their own request-ID files, so regular playback
status cannot overwrite a fresh-settings response. File reads and JSON decoding
run detached, and playback generation IDs prevent preset snapshots resetting
the playhead. Hidden or disabled drawers ignore playback callbacks.

`AppModel+Effects.effectsActionTargets` follows selected Map dots, and normal
selection otherwise. Source protection is refreshed before bounce rather than
walking every library URL during auditions. `playSample`, region playback,
Inspector Stop and recording share `stopAudition`; trims, sound edits and
project audition adjustments reach the live path. Dry-player stop callbacks
cannot clear a newly started effects audition.

Validation uses the Gain fixture in `Tests/Fixtures/VST3Gain.mm` and
`VST3LiveTests`: short-block controls, bypass, editor ownership, real-time mode,
cancellation, duplicate bundles and fresh-settings replies. The warm-helper
test opens the editor, verifies its gain and hidden state in the first block
of a ten-second sample, then stops and cancels it. The final build adds no
compiler warnings beyond the existing CLT linker search-path warnings; all
444 tests in 94 suites pass. An earlier full run overlapped a snapshot and
hit the warm-helper test's generic timeout; the six-test live suite passed
alone, then the full suite passed with no snapshot running. The exact stalled
operation was not recorded in that first run. Live test waits now report their
action and last status, and surface helper errors immediately.

Debug snapshot exercise checks playback without busy-control changes, removal
with an editor open, duplicate-chain reorder/playback, Map selection and Stop.
The same workbench removal action as the card was exercised; the native
accessibility traversal could not expose SwiftUI's Remove button for a press.
Light and dark two-card Library captures and a two-card Map capture were read,
including a 1280 by 740 window. One earlier Map exercise timed out; repeating
with precise timeout diagnostics passed with Hover to play enabled and no
app or effect error. Its cause was not reproduced; Map hover can supersede a
requested audition, so the harness now records the awaited action and state.

UI runtime verification used macOS 26.7.2. The macOS 14 deployment target
builds, but that older runtime and
third-party commercial plug-in editors were unavailable for verification.

`CLAP_SNAPSHOT_EFFECTS_EXERCISE=1`, an effects report path and
