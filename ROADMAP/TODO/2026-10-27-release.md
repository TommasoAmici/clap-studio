# GitHub Release

Let's ensure that the app is not released if the version has not increased since the previous release

- [x] Publish only when the app version exceeds the latest published version.

## Implementation context

`scripts/check-release-version.py` reads `CFBundleShortVersionString` directly
from the bundle script before any app or model build. It compares three numeric
version parts against GitHub's latest published stable release; the existing
`vX.Y.Z-build.N` and plain version tags are supported, but build numbers do not
permit another publication. Equal and older versions skip the release job.

A missing latest release is accepted only after GitHub confirms access to the
repository. Authentication, network, rate-limit and unreadable-release failures
stop the workflow without enabling publication. The guard writes its output
only after a successful lookup and decision. A second check uses the built
app's version immediately before `gh release create`.

The workflow uses one repository-wide concurrency group for pushes and manual
refs. This prevents two queued runs with the same app version from both passing
the first guard before either publishes. An already running release finishes;
GitHub may replace older pending runs with the latest one.

The release and work skills, `AGENTS.md`, and the README now distinguish a
workflow run from publication. The changelog preparation remains a separate
documentation commit before the version bump. No app version was changed or
release published while implementing this guard.

Validation: the guard tests first failed because the helper did not exist.
Eight Python behavior tests now pass, covering numeric comparison, ignored
build numbers, invalid release details, first release, unreadable repositories,
HTTP/network failures and writing no successful output after a failed check.
Workflow YAML and every shell block parse. The actual publication shell block
was exercised with fake Python/GitHub commands: `false` skips, lookup failure
stops, and only `true` reaches publication. The app builds with the existing
Command Line Tools search-path warnings and no new warnings; all 423 Swift
tests pass. No UI or audio behavior changed, so no snapshot is needed.

A read-only live comparison was attempted but could not finish: local Python
could not verify the HTTPS certificate, and a curl API request returned 403.
TLS verification remains enabled, so this environment exercises the safe
failure path. Actual GitHub publication remains unverified locally.
The skill validator rejects the existing `disable-model-invocation` field;
the user-required invocation setting is preserved.
