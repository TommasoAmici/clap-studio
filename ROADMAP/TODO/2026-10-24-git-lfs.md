## Implementation context

- `.gitattributes` scopes LFS to PNG, GIF, JPEG, WebP and AVIF files recursively
  inside `media/`; Markdown and application icons stay in ordinary Git.
- `scripts/setup-lfs.sh` is called by setup before mise. Normal setup installs
  missing Git LFS through existing Homebrew and initializes repository-local
  filters and hooks. `--check` reads the version only; `--media` explicitly
  downloads the media. Existing custom hooks are not forced out of the way.
- `scripts/test-setup.sh` uses fake Git and Homebrew to keep setup tests from
  touching actual configuration or installing packages. `scripts/test-lfs.sh`
  uses disposable repositories to check attributes, canonical pointers, a
  CI-style checkout against a remote with no LFS objects, and byte-preserving
  restoration from a local cache.
- History migration must run in a fully independent clone: worktrees share
  refs, configuration and hooks with the main repository. No shared hooks or
  configuration are changed by this worker; filters are supplied per process.
  The current-assets commit is separate from replacing historical commits.
- Upstream `git-lfs-migrate` documentation distinguishes current-branch
  conversion from `--everything`, which considers all reachable commits.
  Migration generates new commit IDs; `--object-map` records the mapping.
  Remote-tracking refs are not advanced automatically. Rehearsal and final
  migration must explicitly account for all branches and tags that retain old
  media history.
