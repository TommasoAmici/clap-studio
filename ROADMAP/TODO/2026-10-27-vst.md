## Implementation context

The Effects panel now centers its empty state in the available content area.
A fixed status line replaces the conditional spinner and playing label, so
rendering a preview does not shift the controls. See the VST3 effects section
in [README](../../README.md).

Loading currently calls third-party code synchronously on the main actor.
Rendering moves only processing off the actor; initialization, controller
queries and destruction still run inside the app. Process isolation is needed
for both crash containment and a bounded response to hung plug-ins.

Native windows and controls retain the macOS 14 deployment target.
The UI slice passed `scripts/build.sh` and all 421 tests. Light and dark
Effects snapshots were inspected on macOS 26.7.2 using a copied SQLite
library with `CLAP_NO_INDEX=1`; the original library and audio were untouched.
Apple’s live Designing for macOS and Windows HIG pages were read through their
JSON endpoints. Native auxiliary windows and standard window controls guide
the editor presentation. Runtime behavior on macOS 14 remains unverified.

### Isolated loading and rendering

`ClapVSTHost` owns all third-party lifecycle and audio calls. Its main run loop
keeps AppKit-dependent plug-ins functional; the app exchanges JSON messages and
scratch audio files through private temporary folders. The app applies trim and
sound edits before dispatch and verifies/atomically installs the returned audio.
The helper never receives the user's bounce destination or source audio path.

`VST3Process` kills and reaps a helper on cancellation or timeout, including
plug-ins ignoring SIGTERM. Loading has a 30-second deadline. Rendering can run
as long as audio blocks continue finishing, with a five-minute inactivity bound.
A background helper watcher exits if the parent app goes away, even when the
helper's main thread is stuck. `_exit` after a reply avoids static destructors.
The executable is bundled beside ClapStudio; a Foundation bundle marker also
finds it when Swift Testing is hosted by xctest.

`VST3ProcessTests` first failed because the supervisor did not exist, then passed
with shell failures and actual native bundles that crash or hang in bundleEntry.
Tests confirm cancellation kills/reaps and the main actor remains available.
The deterministic VST3 gain fixture exercises real parameter discovery and
stereo rendering without installed vendor effects; existing source, hard-link,
trim and cancellation protections remain covered by `VST3RenderTests`.
The isolation slice passed `scripts/build.sh` with only the existing SDK
linker search-path warnings, all 427 tests, and an inspected Effects snapshot
with the native gain fixture loaded. Both helper startup and actual stereo
processing were verified on macOS 26.7.2.
