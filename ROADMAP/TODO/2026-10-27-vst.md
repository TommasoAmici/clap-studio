## Implementation context

The Effects panel now centers its empty state in the available content area.
A fixed status line replaces the conditional spinner and playing label, so
rendering a preview does not shift the controls. See the VST3 effects section
in [README](../../README.md).

Loading currently calls third-party code synchronously on the main actor.
Rendering moves only processing off the actor; initialization, controller
queries and destruction still run inside the app. Process isolation is needed
for both crash containment and a bounded response to hung plug-ins.

Native windows and controls retain the macOS 14 deployment target.
The UI slice passed `scripts/build.sh` and all 421 tests. Light and dark
Effects snapshots were inspected on macOS 26.7.2 using a copied SQLite
library with `CLAP_NO_INDEX=1`; the original library and audio were untouched.
Apple’s live Designing for macOS and Windows HIG pages were read through their
JSON endpoints. Native auxiliary windows and standard window controls guide
the editor presentation. Runtime behavior on macOS 14 remains unverified.
