## Implementation context

The Effects panel now centers its empty state in the available content area.
A fixed status line replaces the conditional spinner and playing label, so
rendering a preview does not shift the controls. See the VST3 effects section
in [README](../../README.md).

Before this change, loading called third-party code synchronously on the main
actor, and only audio processing moved off that actor. Initialization,
controller queries and destruction still ran inside the app. This motivated
process isolation for both crash containment and bounded response to hangs.

Native windows and controls retain the macOS 14 deployment target.
The UI slice passed `scripts/build.sh` and all 421 tests. Light and dark
Effects snapshots were inspected on macOS 26.7.2 using a copied SQLite
library with `CLAP_NO_INDEX=1`; the original library and audio were untouched.
Apple’s live Designing for macOS and Windows HIG pages were read through their
JSON endpoints. Native auxiliary windows and standard window controls guide
the editor presentation. Runtime behavior on macOS 14 remains unverified.

### Isolated loading and rendering

`ClapVSTHost` owns all third-party lifecycle and audio calls. Its main run loop
keeps AppKit-dependent plug-ins functional; the app exchanges JSON messages and
scratch audio files through private temporary folders. The app applies trim and
sound edits before dispatch and verifies/atomically installs the returned audio.
The helper never receives the user's bounce destination or source audio path.

`VST3Process` kills and reaps a helper on cancellation or timeout, including
plug-ins ignoring SIGTERM. Loading has a 30-second deadline. Rendering can run
as long as audio blocks continue finishing, with a five-minute inactivity bound.
A background helper watcher exits if the parent app goes away, even when the
helper's main thread is stuck. `_exit` after a reply avoids static destructors.
The executable is bundled beside ClapStudio; a Foundation bundle marker also
finds it when Swift Testing is hosted by xctest.

`VST3ProcessTests` first failed because the supervisor did not exist, then passed
with shell failures and actual native bundles that crash or hang in bundleEntry.
Tests confirm cancellation kills/reaps and the main actor remains available.
The deterministic VST3 gain fixture exercises real parameter discovery and
stereo rendering without installed vendor effects; existing source, hard-link,
trim and cancellation protections remain covered by `VST3RenderTests`.
The isolation slice passed `scripts/build.sh` with only the existing SDK
linker search-path warnings, all 427 tests, and an inspected Effects snapshot
with the native gain fixture loaded. Both helper startup and actual stereo
processing were verified on macOS 26.7.2.

### Manufacturer editors and saved settings

`VST3Editor.cpp` attaches the official IPlugView NSView to the helper's native
window. `NativeEditor` supports standard close controls, Command-W, text editing
commands, keyboard/focus forwarding and the plug-in's sizing constraints.
The Effects row shows Open Editor when that view exists; generic sliders remain
for effects that supply none. Closing captures the recipe; Cancel preserves the
previous recipe. Preview and bounce follow after closing the editor.

`VST3Instance.snapshot` saves component and controller state where supported,
in addition to the exposed normalized parameter values. Restoring those blobs
before parameters preserves manufacturer presets and hidden settings. Each
state is bounded to 16 MiB, so both fit within the 64 MiB message limit. The
mandatory IComponentHandler and factory3 host context are now provided.
`Stream` supports bounded file-like seeking past EOF and zero-filled holes;
the native fixture reserves a state header to exercise this path.

The editor heartbeat runs in the main run loop, including tracking and modal
modes. A blocked controller stops it; the app kills/reaps the helper after
30 seconds without a heartbeat. A responsive editor has no total time limit.
The background parent watcher is independent and never refreshes this heartbeat.

Native tests exposed a Foundation Process affinity issue: polling with an
async sleep could resume on another thread, leaving waitUntilExit stuck after
the child exited. A sampled test runner confirmed the wait inside Foundation's
CFRunLoop. Supervision now launches, polls, kills and reaps on a single
DispatchQueue worker with a locked cancellation flag. Tests cover cancellation
before dispatch, actual crash/hang, and repeated short helper requests.

`VST3EditorTests` first failed for the missing editor/state API. Its native
fixture verifies attachment, a hidden preset offset surviving a fresh render,
recipe identity and generic fallback. Native editor and chain snapshots were
inspected on macOS 26.7.2. Real manufacturer plug-ins were not installed on this
Mac, so their individual editor compatibility remains unverified; the fixture
uses the official vendored interfaces and actual AppKit controls. macOS 14
runtime behavior remains unverified.

The watchdog uses a 30-second startup deadline before the first heartbeat,
then the appropriate editor/render inactivity deadline. It reads fresh file
attributes and measures elapsed time with ContinuousClock. Tests exercise both
continued heartbeats and a stopped heartbeat. Process fixtures are serialized;
a dedicated worker cancels after the child writes its readiness marker. This
keeps the test meaningful when concurrent DSP/model cases delay a Swift test
coroutine, instead of confusing delayed test resumption with a live helper.

Final validation: `scripts/build.sh` passed with only pre-existing CLT linker
search-path warnings; all 434 tests in 93 suites passed. `scripts/bundle.sh`
passed using an empty optional-model directory, `codesign --verify --deep
--strict` passed, and the signed bundled release helper loaded the native gain
fixture and captured both state blobs. Inspected light/dark empty, loaded
chain and manufacturer-view snapshots use only scratch library data. Real
vendor plug-ins and the macOS 14 runtime remain the compatibility gaps.
