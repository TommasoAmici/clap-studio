# Website

Using the images available in ./media, design a landing page to showcase this application.
We have both light and dark theme images, so the website should show the one matching the current user preferred color scheme
in the browser.

In particular, highlight the capabilities built for the ALM Salmple.

The website should be visually captivating, intense, beautiful, colorful.

Write it in ./website

It should be a static website.

- [x] Build and verify the responsive landing page with automatic light/dark screenshots and an ALM Squid Salmple showcase.

## Implementation context

- `website/index.html`, `styles.css` and `responsive.css` use an oversized
  poster style in yellow, pink, violet and orange. Real screenshots remain the
  main product visuals; all claims come from the feature reference in README.
- Native `picture` sources follow `prefers-color-scheme`, including when the
  preference changes while the page is open. The default Together preview and
  all copy work without JavaScript; `site.js` adds the native button group for
  Drums, Melody and Together, preserving the active color scheme.
- `scripts/website.sh` makes a self-contained output folder using Python's
  standard library. Source image paths point to the existing `media/` folder,
  so no second set of images is tracked. Builds verify PNG signatures and
  refuse missing images or Git LFS pointers before copying anything.
- The type uses locally available condensed and system fonts, so the page
  requires no font download or third-party service. The decorative text strip
  is static; reduced motion also removes hover transitions and smooth scrolling.
- Verified the app build with no new warnings and 399 tests in 87 Swift
  suites. `scripts/test-website.sh` checks portable asset paths, every music
  view in both appearances, missing media, Git LFS pointers and source protection.
- Browser checks covered desktop and mobile in both appearances, no horizontal
  overflow at 320, 390, 768 and 1440 pixels, keyboard music controls, section
  navigation, reduced motion and the JavaScript-free fallback. Theme changes
  kept the same document and selected musical view. Every displayed screenshot
  switched to the corresponding light or dark file; no browser errors occurred.
- Agent-browser's cached launcher restarts Chrome when launch settings change.
  The live theme check therefore attached Playwright to that isolated Chrome's
  CDP connection. Full-page evidence eagerly loaded screenshots for capture
  only; the page itself keeps below-the-fold images lazy.
