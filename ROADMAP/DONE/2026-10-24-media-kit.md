# Images for website and media kit
Please seed the app with samples and take screenshots of different views in both light and dark mode.
These images will be shown in our social media and our website so they must be high resolution images.
Store the screenshots in ./media in this repo.

Ideally, we should end up with a script we can run in the future to update the screenshots. So when the UI changes, we can regenerate these screenshots to include the changes.

## Implementation context

`Sources/ClapMediaSeed/main.swift` builds a fresh library through ClapCore's
storage APIs, with 384 original synthesised WAVs. Descriptors are measured from
the audio; category labels and cached map coordinates are demonstration data.
The seeder refuses to replace an existing database.

`scripts/media-kit.sh` runs the captures sequentially with scratch library and
model folders and indexing disabled. A copy of the debug executable named
`ClapStudioMedia` keeps its preference domain separate from the installed app.
`DebugSnapshot` supports an app-only appearance override and explicit bitmap
scale, so the PNG resolution does not depend on the attached display.
Demo vectors are L2-normalised before saving, as required by the cosine index;
the fixed map coordinates remain separate. Connected USB drives are skipped
during media captures so personal drive names cannot appear in the images.

AppKit's bitmap cache omits Metal layer contents. Debug map captures therefore
render the real dot and highlight pipelines into an offscreen Metal texture,
then temporarily add those pixels inside the map view before caching the
window. This keeps the map controls and legend above the captured dots.

The seeder is built in release while the captured app stays debug: generating
all sounds and descriptors took 0.98 seconds in release, versus 79.78 seconds
in debug. Sound families use independent tasks and analyzers; only their
returned dictionaries are merged, sequentially. A fixed shuffle seed shows
different sound families in the list rather than a screen of one name prefix.

Validation: debug build and the full 386-test / 84-suite run passed with no
new compiler warnings (the existing Command Line Tools linker search-path
warnings remain). All eight final PNGs were read and checked at 3200 × 2000;
the waveform inspector, four drum tracks, two melody tracks and Metal dots
are populated in both appearances. The complete generator took 174 seconds,
including a release rebuild; warm seeding itself took about one second.

A read-only check of the generated database found 384 OK samples and unit
vector squared-length errors below 3e-7. A nonempty destination containing
a marker WAV was refused with its bytes unchanged and no database created.
The capture removed its scratch library. The separate preference domain
was verified with `defaults read ClapStudioMedia project.bpm` returning 124.

See [the media guide](../../media/README.md) for regeneration and image contents.

Integration keeps both capture paths in `DebugSnapshot`: `--update` captures
the native alert window with existing permission, while other modes use the
scaled bitmap cache and temporary Metal pixels. The final media set is
regenerated from the combined app so future UI changes are represented.
The explicit scale applies to bitmap captures; native update captures use the
display's resolution.
The combined build, 398-test / 86-suite run and full 100,000-sample benchmark
passed. All eight regenerated PNGs were inspected again at 3200 × 2000, and
the native update prompt was captured and read after resolving the shared
snapshot helper.
